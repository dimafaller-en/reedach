# reedach-server

Сервер Reedach: орфография (hunspell), морфология (Az.js со словарями OpenCorpora) и
подсказки по стилю из ядра `reedach` — одним запросом. Работает на вашем сервере,
тексты никуда не уходят, не сохраняются и не пишутся в журнал.

Подключить можно двумя способами:

- **библиотекой** — вызывать `check()` прямо в своём Node-приложении, без отдельного сервиса;
- **по HTTP** — запустить Docker-образ и отправлять запросы с сайта.

Для орфографии нужна программа `hunspell` (в Alpine: `apk add hunspell`, в Debian и
Ubuntu: `apt install hunspell`). В Docker-образе она уже есть.

## Библиотекой

```js
import {check} from 'reedach-server';

const {issues} = await check({
  markdown: 'В настоящее время мы осуществляем доставку.',
  ignore: ['Glaskraft'],          // слова автора: формы тоже принимаются
  disable: ['intensifiers'],      // выключить правило по id или целую категорию
});
```

## По HTTP

```bash
docker build -t reedach .
docker run -d -p 3000:3000 -e REEDACH_KEYS="длинный-ключ-сайта=https://ваш-сайт.ru; ключ-для-сервера-сайта" reedach
```

Без ключа сервер не запускается.

### Ключи

`REEDACH_KEYS` — список ключей через `;`. Каждый ключ не короче 16 символов. После `=`
через запятую перечисляются сайты, со страниц которых этот ключ можно использовать
прямо из браузера.

- **Ключ с сайтами** работает со страниц этих сайтов и с любого сервера.
- **Ключ без сайтов** работает только с сервера: браузер с ним получит отказ.

Ключ в коде страницы виден любому посетителю, секретом он не является. Чужой сайт его
использовать не сможет, но скрипт вне браузера сможет, а сдержат его только лимиты.
Надёжнее отправлять запросы через сервер своего сайта и не открывать Reedach в интернет.

### Запросы

Ключ передаётся в заголовке `Authorization: Bearer <ключ>`, тело запроса — JSON.

**`POST /v1/check`** — проверить текст. Передайте одно из трёх:

| Поле | Что это | Куда указывают `start` и `end` |
|---|---|---|
| `markdown` | Markdown-текст | в исходный текст |
| `text` | обычный текст, абзацы через пустую строку | в исходный текст |
| `blocks` | `[{text, kind}]`, где `kind` — `p`, `li` или `h` | в текст блока номер `block` |

Необязательные поля:

- `ignore` — слова автора;
- `disable` — id правил или категории, которые нужно выключить;
- `checks` — какие проверки запускать: `spelling`, `morph`, `style` (по умолчанию все).

Ответ:

```json
{"issues": [
  {"start": 0, "end": 17, "id": "time-parasite-start", "category": "time", "label": "Паразит времени",
   "message": "Вступление о нынешнем времени ничего не добавляет к предложению.", "fix": "…"},
  {"start": 46, "end": 52, "id": "spelling", "category": "spelling", "label": "Орфография",
   "word": "превет", "suggestions": ["привет", "…"], "message": "…", "fix": "…"}
]}
```

Подбор вариантов исправления медленный, примерно 0,3 секунды на слово. Поэтому варианты
приходят сразу только для первых десяти ошибок, а на всё отводится не больше трёх секунд.
У остальных ошибок `suggestions: null`: варианты можно запросить отдельно, когда автор
нажмёт на слово.

**`POST /v1/suggest`** — `{"words": ["превет"]}` → `{"suggestions": {"превет": ["привет", …]}}`,
до 20 слов за раз.

**`GET /v1/rules`** — все правила с категориями и объяснениями, например для страницы
настроек «какие проверки включены».

**`GET /health`** — проверка, что сервер работает. Ключ не нужен.

Ошибки приходят в виде `{"error": {"code": "…", "message": "…"}}`: 401 — нет ключа,
403 — ключ не для этого сайта, 413 — слишком большой текст, 422 — неверные поля,
503 — сервер занят (в заголовке `Retry-After` указано, через сколько секунд повторить).

### Настройки

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `REEDACH_KEYS` | — (обязательно) | ключи доступа |
| `PORT` | `3000` | порт |
| `HOST` | `0.0.0.0` | адрес |
| `REEDACH_MAX_BYTES` | `1000000` | максимальный размер запроса |
| `REEDACH_CONCURRENCY` | `2` | сколько проверок идёт одновременно |
| `REEDACH_QUEUE` | `20` | сколько запросов может ждать; остальные получат 503 |

## Как устроена орфография

Ошибки ищет короткий запуск `hunspell -l` на каждый запрос: это быстро, тысячи слов за
доли секунды. Варианты подбирает один постоянно запущенный `hunspell -a`:

- в него уходят только слова из букв, каждое отдельной строкой со служебным знаком в
  начале, поэтому никакой текст не станет командой hunspell;
- слова автора отсеиваются в Node и в hunspell не добавляются, поэтому между запросами
  ничего не запоминается;
- слова идут по одному, и ответы разных запросов не перепутаются;
- зависший процесс убивается и запускается заново, а после 2000 слов процесс
  перезапускается в любом случае.
